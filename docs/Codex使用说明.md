# ClearPane for Codex

Codex 版本与 Antigravity 版本共用 Markdown 渲染、正文批注、待发送清单和文件更新逻辑。Codex 入口是本地 stdio MCP 服务，附带 Skill、MCP Apps 阅读面板和受保护的 localhost 阅读页。

## 构建与启动

需要 Node.js 22 或更高版本。

```powershell
npm ci
npm run build:codex
npm run start:codex -- "." "README.md"
```

最后一条命令输出本地阅读链接；服务运行期间保持该终端打开。在 Codex 当前聊天的内置浏览器打开此链接，即可分屏阅读。直接启动适合开发检查，插件启用后由 MCP 工具管理服务。

可分发目录为 `dist/codex-clearpane/`，包含服务、网页、字体、技能、图标与依赖许可证。该目录运行时只需要 Node.js，无需 `npm install`。浏览器包包含 KaTeX 字体和 Mermaid，本地文档、公式、图表和图片可离线使用；网络图片仍需要网络。

## 安装插件

构建后运行：

```powershell
npm run install:codex
```

安装脚本将插件复制到用户目录的 `.codex/plugins/clearpane/`，并合并 `.agents/plugins/marketplace.json`，保留其他插件。打开桌面应用的插件目录，选择对应的本地来源，安装并启用 ClearPane，然后新建聊天。若没有刷新，重启桌面应用。运行脚本只准备本地来源，不会替用户点击安装或重启应用。

更新前先保存需要的评论并停用旧服务，然后运行：

```powershell
npm run build:codex
npm run install:codex -- --update
```

旧插件和原 marketplace 文件备份到 `.codex/clearpane-backups/<时间戳>/`。可用 `--home <目录>` 指定独立安装配置，便于测试。

仅需 MCP 时，也可自行配置绝对路径：

```toml
[mcp_servers.clearpane]
command = "node"
args = ["D:/你的路径/codex-clearpane/server.mjs"]
```

此方式不会同时安装 Skill；优先使用完整插件目录。

## 在 Codex 中使用

启用插件后，可说：“用 ClearPane 打开当前项目的 README，等我批注后再修改。”

Agent 调用 `open_reader`，显式传入当前任务的绝对工作区目录、可选文档路径和阅读会话名称。宿主支持 MCP Apps 时显示阅读面板；否则在当前聊天的内置浏览器打开返回的 localhost 链接。

安装前已打开的聊天可能没有刷新 MCP 工具列表。0.1.2 起，随附 Skill 会在 `open_reader` 缺失时调用插件中的备用入口，并在当前聊天内置浏览器打开完整阅读器。无需把原始文件面板当作插件入口。手动启动同一路径的命令为 `node "<插件目录>/start.mjs" --background "<工作区绝对路径>" "<文档绝对路径>"`，返回包含 `url`、`pid` 的 JSON。该进程在启动命令结束后继续运行，八小时后关闭；保存评论后也可停止返回的 PID。每次启动创建独立进程，评审中复用同一链接。

1. 从工作区文章列表搜索文件，或输入已授权范围内的 Markdown 完整路径。
2. 选中文字，点击“评论选区”或浮动“评论”，填写意见并加入待发送。添加评论不会触发 Agent。
3. 点击顶部“待发送”，修改各条意见并填写统一指令。
4. MCP 面板在宿主声明支持文本消息时提供“统一发送”。浏览器模式提供“复制整批评论”，用户粘贴到目标聊天发送。复制后仍保留评论；剪贴板权限被拒绝时会出现可手动复制的文本框。

批量文本包含源文件路径、引用、评论及统一指令。成功发送表示宿主已接收消息，不表示文件已修改；请在聊天中确认处理结果。拒绝发送会保留评论；超时或连接异常会锁定发送，需先检查目标聊天，再手动解锁，防止重复提交。

宿主提供网页 Annotation API 时，正文选择后还可使用“宿主批注”。它打开宿主编辑器，最终由用户提交；该批注不进入 ClearPane 待发送清单。没有此 API 时隐藏按钮。

## 草稿、更新与访问范围

- 每次 `open_reader` 创建独立阅读会话。复用同一个链接，可在服务运行期间恢复评论、统一指令和阅读位置。重新调用工具会创建新的空白会话。
- 草稿存在服务内存中。重启服务、插件更新或连续 8 小时不访问后，草稿失效。关闭页面不会立即删除草稿；最多同时保留 64 个阅读会话，达到上限时复用已有链接，或保存评论后重启服务。
- 同一链接在多个标签页打开时，状态版本检查会拒绝过期写入并显示缓存错误。评审时使用一个标签页。
- 每 2 秒检查文件更新；选中文字、编辑评论、查看待发送或隐藏页面时暂停，结束交互后恢复。原文变化会提示已有评论的来源已更新。
- 只读取显式授权目录中的文件；符号链接或目录联接不能扩大范围。工具显式打开的外部文档仅授权该文档及其目录内的图片，不会将同目录其他文档加入授权。
- 仅支持本地绝对路径、UTF-8 `.md` / `.markdown`，正文上限 1 MiB，本地图片上限 20 MiB。UNC 网络共享、设备路径和文件数据流被拒绝。
- 服务只监听 `127.0.0.1` 的随机端口，使用独立会话凭证并校验 Host、Origin 和请求大小。凭证位于链接片段，载入后移出地址栏；不要分享完整阅读链接。
- 排版设置存放在用户目录 `.codex/clearpane/settings.json`，包括字号、行高和色彩模式。正文和评论不写入该文件。

## 已验证与宿主限制

`npm run build:all` 构建两个版本，`npm test` 运行回归；`npm run test:codex` 构建并运行 Codex 专项检查。UI 检查需要安装 `agent-browser` 和 Chromium，可通过 `AGENT_BROWSER_BIN` 指定可执行文件。

专项检查覆盖真实 stdio MCP 握手和资源读取、文件授权、会话隔离、安装更新，以及 Chromium 中的公式、Mermaid、本地图片、批注复制、刷新恢复、文件更新、320/375px 窄屏。使用官方 AppBridge 的测试宿主验证一次整批消息、拒绝、超时锁定和主题变化；测试不会向真实 Codex 聊天发送消息。

2026-10-28 已在本机 Codex 内置浏览器实际打开本地阅读页，确认自动载入文档和正文排版。宿主复用 iframe 接收另一阅读会话时，旧面板停止操作并要求重新打开，防止旧草稿提交到新目标。

当前 Codex 桌面是否渲染第三方 MCP Apps、是否授予 `ui/message`、是否暴露原生批注 API，仍由客户端版本和权限决定。协议测试通过不等于真实桌面宿主验收。浏览器复制路线可独立工作，不依赖这些接口，也不会接管桌面聊天或使用私有宿主管道。

MCP UI 的资源策略默认不允许外部网络图片，受宿主限制时会显示加载失败提示；需要查看网络图片时使用返回的本地浏览器阅读页。本地图片通过鉴权工具传输。阅读页和 MCP 面板均只读源文档，只有 Agent 收到用户明确提交的评审后才执行修改。

本地安装与公开上架是不同流程；插件包未发布到公共插件目录。有关来源及能力边界，见 [可行性研究](Codex版本可行性研究.md)。
